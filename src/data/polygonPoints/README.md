# Polygon Points — Drive-Time Isochrones

This folder holds the boundary polygons drawn on the community-journal **Search** map.

## What these polygons are

Every boundary is a **drive-time isochrone** — a shape that answers *"how far can you
drive on real roads from this pin in N minutes?"* — generated by the
[Valhalla routing engine](https://valhalla.github.io/valhalla/) but used for the
**map render only**.

They are **not** OSM/Nominatim administrative ward boundaries. The polygon is built
*around* each area's pin, so **every journal pin is guaranteed to lie inside its own
region** — unlike official ward boundaries, where the pin often falls outside. The shape
reads as the liveable, reachable catchment around the chosen micro-market, and the pin
(`latlong`) stays authoritative and is never edited to fit a boundary.

## Data pipeline

```
journal JSON                    index.ts                    polygonPoints/*.ts
------------                    --------                    ------------------
exploredAreas[]                 POLYGON_POINTS              export const <key>IsochronePoints
  ├─ polygonKey ──────────────► getPolygonPoints(key) ───►  Array<[number, number]>
  └─ latlong (pin, authoritative)
```

1. Each `exploredAreas` entry in a journal JSON carries a `polygonKey` (e.g. `"whitefield"`).
2. `src/data/polygonPoints/index.ts` maps that key to the imported TS export.
3. The TS file `polygonPoints<Key>.ts` contains the `Array<[number, number]>` of `[lat, lng]` vertices.
4. The map component calls `getPolygonPoints(area.polygonKey)` and feeds it to Leaflet.

Points live **only in TS** (never inlined into JSON) so there is a single source of truth
and JSON stays human-readable.

## Regenerating a single area

Use `scripts/generate-isochrone.mjs`:

```bash
node scripts/generate-isochrone.mjs \
  --name "Whitefield" \
  --lat 12.971480 --lon 77.737086 \
  --time 20 --denoise 0.1 --generalize 150 \
  --out src/data/polygonPoints/polygonPointsWhitefield.ts \
  --overwrite
```

- `--time` — reachable drive minutes (Valhalla allows 5–120).
- `--denoise` — 0..1; trims tiny inlets/outliers. `0.1` is the current default combo.
- `--generalize` — meters; smooths out jagged street-snapping vertices **without**
  shifting the region or dropping the origin pin. `150` gives the current clean shapes.
- `--out` — write straight to the *wired* file path (prevents the stray duplicate the
  default filename derivation can create). Keep the export name `export const <key>IsochronePoints`.

> If you omit `--out`, the script writes to `polygonPoints<CamelName>.ts` derived from
> `--name`. Unless that `CamelName` happens to equal the wired file, this creates a
> duplicate that must be deleted — prefer passing `--out`.

> **Auto-escalation applies here too**: if the pin isn't inside the requested `--time`
> isochrone, the tool steps up (5→8→10→12→15→20→30→40→60→90 min) until it finds one,
> or throws with `--no-escalate`. Use `--max-time <N>` to cap the reach.

## Regenerating everything

```bash
node scripts/generate-isochrone.mjs --batch              # all areas, time=20 generalize=150 denoise=0.1, auto-escalate
node scripts/generate-isochrone.mjs --batch --dry-run    # print the plan, fetch nothing
node scripts/generate-isochrone.mjs --batch --time 25    # override reach time
node scripts/generate-isochrone.mjs --batch --generalize 200
node scripts/generate-isochrone.mjs --batch --denoise 0.2
node scripts/generate-isochrone.mjs --batch --no-escalate  # disable auto-escalation
```

The `--batch` mode reads the pins from the journal JSONs, maps each `polygonKey` to the
wired TS file, and writes the smoothed shape directly, preserving the `<key>IsochronePoints`
export name. When `--time` / `--generalize` / `--denoise` are omitted it defaults to the
standard smoothing combo (`20` / `150` / `0.1`).

### Auto-escalation

By default the generator **auto-escalates**: it starts at `--time`, then steps a ladder
(`5 → 8 → 10 → 12 → 15 → 20 → 30 → 40 → 60 → 90` min) until the origin pin falls *inside*
the isochrone, writing the smallest qualifying shape and recording that reach time in the
file header. Starting low lets naturally small / adjacent micro-markets (e.g. South
Bengaluru: JP Nagar / Jayanagar / Banashankari) land on a tight, non-overlapping shape,
while still capturing sparse-road pins (like `devanahalliPlottedArc`, which needs 40 min)
that a single short run would miss.

- `--escalate` / `--no-escalate` — toggle auto-escalation (default **ON**).
- `--max-time <N>` — hard cap in minutes (default `90`; Valhalla rejects `120`).
- With `--no-escalate`, a pin that falls outside the requested isochrone throws instead
  of writing a bad file.

Sanity-check the results after any run:

```bash
node scripts/generate-isochrone.mjs --verify
```

This reports ring-closure, pin-inside, point count, and export-name consistency for every area.

## Adding a new area

1. Add `polygonKey` (+ the pin `latlong`) to the journal JSON's `exploredAreas`.
2. Import the vertex array in `src/data/polygonPoints/index.ts` and register the key.
3. Generate the TS file (`generate-isochrone.mjs --out src/data/polygonPoints/polygon<...>.ts --overwrite`).
4. Run `node scripts/generate-isochrone.mjs --verify` and confirm `pinInside=true`.

## Note on the data source

The `generate-isochrone.mjs` script talks to the public, community-run demo server at
`https://valhalla1.openstreetmap.de`. It is free and keyless but rate-limited — keep batch
runs modest (the current full sweep is ~17 requests). For production/CI, run your own
Valhalla or OSRM instance and point `VALHALLA_BASE` at it.
